# Unwatched — Roadmap & Epic Backlog

Surveillance-aware route planner on Overture (roads) + DeFlock/OpenStreetMap
(ALPR/Flock cameras). This doc tracks the **work still to do**, organized as
epics. It's a living backlog, not a spec.

## Product thesis

Our differentiator is **not more dots** — DeFlock already maps ~99k ALPRs
nationally. Our edge is **interpretation, action, and trust**: turning a camera
map into a personal exposure number, a rights-and-action layer, and an honest,
inspectable tool a county GOP committee *and* a legal-aid clinic can both link
without flinching. Let the data be the argument.

## Architecture constraints (respect these when building)

- **Static SPA** (Vite + React + TS + MapLibre), **client-side A\* routing** in a
  Web Worker. No backend.
- **Data is static JSON** committed under `web/public/data/**` and served by the
  site itself (`/data`), generated by a **Python pipeline**. No backend, no
  object store — new data = run the pipeline locally and commit the JSON.
- **Registry is the source of truth**: `scripts/cities.json` (+ `metros.json`
  for curated metro boxes). The frontend index is rebuilt from the registry.
- **Privacy is load-bearing**: no accounts, no telemetry, no route logging,
  client-side compute. Do not regress this.

## Key datasets that unblock Epic B

Most of Epic B is gated on curation you build once and grow:

- **`agencies.json`** — operator → `{retention, sharing count, last audit,
  renewal, council contact}`. Start with **only the operators already in our 28
  cities** (tractable list). → unblocks B2, B3.
- **`jurisdictions.json`** — state/city → `{retention cap, warrant rule, 4A
  status, litigation, bill}`. Start with **VA (Norfolk / Schmidt v. Norfolk
  anchor)**. → unblocks B1, B2.

## Open decisions (need a human call, not code)

1. **Governance / exit** (F3) — decide before there's anything worth buying.
2. **Coverage normalization** — publicly show coverage-quality/bias badges? (Lean yes; it's the honest move.)
3. **Demographics framing** (Epic D) — how loud, and gated behind confounder controls?
4. **Funding model** — must **not** grow with surveillance (no per-user/per-camera). Pick a success metric that isn't MAU (contracts canceled, records filed, cameras removed).

## Recommended sequencing

1. **Sprint 1 — Epic A (trust bundle):** A1–A4. Days, not weeks.
2. **Sprint 2 — Epic B start:** `jurisdictions.json` → B1, then B2 (VA first).
3. **Sprint 3 — Epic B cont.:** `agencies.json` → B3.
4. **Sprint 4 — Epic C:** C1 national ingest + C2 validation.
5. **Then the big swings:** Epic E (temperature map) and Epic D (moat analysis) in parallel — both are `→ static JSON` jobs reusing the existing pipeline pattern.

## Legal / licensing notes

- Camera data flows through OpenStreetMap → **ODbL**: commercial use OK,
  **attribution mandatory**, derived databases inherit **share-alike**. We can
  sell access/service; we can't enclose the commons. (Overture terms are
  separate — check for its layers.)
- Never sell the enriched agency/sharing-graph dataset downstream. Never monetize
  the user side. Don't paywall the safety-critical layer (map/routes/exposure).
